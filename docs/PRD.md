# claude-config-ko — PRD

Claude Code의 `/config` 설정 메뉴를 한국어로 읽게 해 주는 모드(플러그인 이름 `config-ko`)다.

## 목차

1. 배경
2. 목표
3. 요구사항
4. 결정 사항
5. 범위 밖
6. 확인된 사실

## 1. 배경

`/config` 메뉴의 줄 이름이 영어이고(`Auto-compact`, `Worktree base ref`), 엔진의 기본 줄에는 설명도 없다. 이름만 보고 무엇이 바뀌는지 알기 어렵다. 사용자는 집 맥과 회사 맥을 함께 쓰므로 두 맥에서 똑같이 보여야 한다.

## 2. 목표

1. `/config`를 열면 각 줄이 `한국어 이름 (English name)`으로 보인다. 메뉴 검색은 한국어와 영어 둘 다 된다.
2. 설명이 필요할 때 `/config-ko`를 치면, 옆 창에서 줄마다 "켜면 무엇이 달라지는지"를 한국어로 읽는다.
3. 설정 값과 동작은 하나도 바뀌지 않는다.

`/config` 메뉴 안에 설명 줄을 넣는 것은 엔진이 막고 있어 하지 않는다(4절, 6절).

## 3. 요구사항

| 번호 | 요구사항 |
| --- | --- |
| R-1 | 엔진이 소유한 `/config` 줄의 이름을 `한국어 (영어 원문)`으로 바꾼다. 영어 원문은 표에 적어 둔 글이 아니라 엔진이 그 순간 준 이름을 쓴다. 엔진이 이름을 바꾸거나 상황에 따라 다른 이름을 줘도(`Teammate mode [overridden: …]`, VS Code의 짧은 이름) 괄호 안은 실제 이름과 같다. 이미 한국어 이름이 붙은 줄에는 다시 붙이지 않는다. |
| R-2 | 줄마다 한국어 설명 한 줄을 `description`으로 붙인다. 엔진이 이미 설명을 준 줄이면 엔진의 설명을 그대로 둔다. 터미널 `/config` 메뉴는 엔진 기본 줄의 설명을 그리지 않으므로(6절) 사람이 설명을 읽는 자리는 R-9의 도움말 창이다. `$.config.list()`를 읽는 곳에는 그대로 전해진다. |
| R-3 | 선택지 값(`dark`, `fresh`, `acceptEdits` 등)은 실제로 저장되는 값이라 바꿀 수 없다(엔진에 훅이 없다). 대신 선택지가 있는 줄은 설명에 값마다 뜻을 적는다(예: `fresh=origin 기본 브랜치에서 깨끗하게 · head=지금 HEAD에서(push 안 한 커밋 포함)`). |
| R-4 | 번역 표에 없는 줄(새 버전에서 생긴 줄, 다른 플러그인의 `userConfig` 줄)은 손대지 않고 엔진이 준 그대로 둔다. |
| R-5 | 설정 값, 키, `/config key=value` 명령, 줄의 순서·숨김·잠금은 건드리지 않는다. 이름과 설명만 바꾼다. |
| R-6 | 메뉴 검색에서 영어 이름으로도 찾을 수 있어야 한다. 이름에 영어 원문을 남기는 이유 중 하나다. |
| R-7 | 집 맥과 회사 맥에 같은 방법으로 설치한다: 공개 GitHub 레포 `JunH-K/claude-config-ko`를 마켓플레이스로 두고 `/plugin install config-ko --marketplace JunH-K/claude-config-ko`. |
| R-8 | 모드의 훅이 실패해도 메뉴는 깨지지 않는다. `config.describe` 훅이 실패하면 엔진이 그 줄을 원래대로 그리고(엔진 동작), `config.set` 훅은 실패해도 값 바꾸기를 막지 않는다(`.catch`가 그대로 넘긴다). |
| R-9 | `/config-ko` 명령은 "설정 도움말" 창을 연다. 창은 `/config`와 같은 순서로 줄마다 `한국어 (영어)` 이름(굵게), 지금 값, 그 아래 흐린 한국어 설명을 보인다. 값은 켬/끔을 한국어로, 나머지는 저장 값 그대로 보이고(비어 있으면 "(없음)", 목록은 쉼표로 잇는다), 조직 설정이 잠근 줄에는 "(잠김)"을 붙인다. 값은 읽기만 하고 바꾸는 것은 `/config`에서 한다. `/config`에서 값을 바꾸면 창도 다시 그린다. 창은 사람이 명령을 칠 때만 열린다(스스로 열리지 않는다). 명령은 사람이 있는 대화형 세션에서만 등록한다(`claude -p`에는 없다). 창을 놓을 자리가 없으면 그렇다고 알린다. |

## 4. 결정 사항

- 2026-10-21 사용자: 영어 원문을 괄호로 같이 둔다, 줄마다 한국어 설명을 붙인다, 공개 레포로 한다.
- 2026-10-21 사용자: 설명을 `/config` 안에 넣는 안(이름 뒤에 짧은 설명 붙이기, 영어를 빼고 설명 붙이기)은 쓰지 않는다. 이름은 `한국어 (English)`로 두고, 설명은 필요할 때 `/config-ko` 창으로 본다. 첫 결정의 "줄마다 한국어 설명"은 이 창으로 채운다(6절의 실험 참고).
- 번역 표는 엔진 2.1.306의 설정 패널 코드에서 뽑은 61개 줄 키 중 60개를 담는다. `apiKey`(사용자 지정 API 키) 줄은 이름 뒤에 키 일부를 굵게 덧붙여 그리므로 손대지 않는다. 이 맥에 보인 줄은 42개(`claude -p`)지만, 줄의 상당수가 기능 플래그·환경에 따라 나타나므로 회사 맥에서는 다른 줄이 보일 수 있다.
- 설명 글은 엔진 설정 스키마의 `.describe()` 문구와 설정 패널 코드를 읽고 쓴다. 근거를 찾지 못한 줄은 줄 이름에서 확실히 말할 수 있는 만큼만 쓴다.
- 켜고 끄는 명령은 두지 않는다. 끄려면 플러그인을 끈다(`claude plugin disable config-ko@claude-config-ko`).
- 레포는 개인 레포라 커밋 작성자를 `JunH-K`로 둔다(레포 안 `git config`로 고정).

## 5. 범위 밖

- 메뉴 틀: 제목, 탭(Settings·Status·Config·Usage·Stats), 검색창, 아래 안내 문구. 고칠 훅이 없다.
- `/config` 메뉴 안의 설명 줄(4절).
- 선택지 값 자체의 한국어 표기(R-3). 메뉴에 보이는 값 글자(`Dark mode`, `Auto`)도 엔진이 그린다.
- 다른 화면(`/permissions`, `/model` 등)의 한국어화.

## 6. 확인된 사실

- 엔진 2.1.306에는 `config.describe` 훅이 있다. `/config` 메뉴가 줄을 하나씩 그릴 때와 `$.config.list()`가 불릴 때마다 불리고, `label`·`description`·`isHidden`을 바꿀 수 있다. `key`와 `provider`는 바꿀 수 없다. 답은 `$.ui.invalidate("config.describe")`나 플러그인 목록이 바뀔 때까지 캐시된다(타입 선언에서 읽음).
- 엔진의 기본 줄은 `provider`가 `{ plugin: 'engine', tier: 'core' }`이고 설명이 없다(2026-10-21 이 맥에서 `claude -p`로 `$.config.list()`를 실행해 42줄 확인. 모드를 켜면 42줄 모두 한국어 이름과 설명을 받았다).
- 대화형 세션은 `claude -p`보다 줄이 많다(쉬는 동안 압축, 피드백 초안, 아티팩트 등). 줄이 환경·기능 플래그에 따라 달라진다.
- 2026-10-21 tmux 실제 세션(2.1.306)에서 확인:
  - 엔진 기본 줄의 이름이 한국어로 바뀌어 보인다.
  - 검색은 한국어("편집기", "시각 형식")와 영어("worktree", "Auto-compact") 둘 다 된다.
  - 엔진 기본 줄의 `description`은 목록에도, 선택형 줄을 연 하위 화면에도 그려지지 않는다. 플러그인 `userConfig` 줄(turn-panel의 편집기)의 설명은 하위 화면에만 그려진다.
  - `/config-ko` 창이 줄마다 이름·값·설명을 보이고, `/config`에서 "팁 보기"를 껐다 켜면 창의 값도 끔·켬으로 바뀐다.
  - GitHub에서 설치한 판(0.1.0)으로 새 세션을 열어도 위와 같다.
- 2026-10-21 실험: `/config` 화면을 그리는 렌더 훅은 없다(`RenderComponent`에 없음). 이름에 설명을 덧붙이면 한 줄로 보이고(`\n`은 무시되어 이어 붙는다) 값 칸이 가장 긴 이름만큼 밀린다. 160칸에서는 보이지만 100칸에서는 이름이 `…`로 잘리고 값이 안 보인다.
